# 研究ポスター案：Design of 3D Data Rendering and Analysis System for Agriculture

## 📌 基本情報
- **タイトル**: Design of 3D Data Rendering and Analysis System for Agriculture
- **サブタイトル**: WebGPUベースの大規模点群データ可視化・解析フレームワーク

---

## 1. 背景・目的

### 背景
- **三次元データ計測の高精度化**
  - 1億点規模以上の大規模データが一般化
  - 農業・河川・建築分野における需要拡大

- **代表的な3Dデータ形式**
  - Lidar、3D点群、メッシュ、標高データ
  - フォーマット: LAS, LAZ, XYZ, TXT, TIF, COPC など

- **既存ツールの課題**
  - Unity, CloudCompare, Open3D, Potree などが存在
  - しかし、**農業分野特有の解析が困難**:
    - 太陽光の照射角度計算
    - 時間帯による影の変化シミュレーション
    - 各点群への光データの付与（熱、温度、反射率）
    - UI/UX を考慮した直感的な操作性

### 研究目的
- **WebGPUを活用した高速レンダリングシステムの構築**
  - ブラウザ上で1億点以上の点群データをリアルタイム表示
  - 農業分野に特化した光・影・熱解析機能の実装
  - アウトオブコアレンダリングによるメモリ効率化

## 2. 提案システムの概要

### システムアーキテクチャ

```
┌─────────────────────────────────────────┐
│  ユーザーインターフェース (Browser)      │
│  - ファイル選択 (COPC/LAS/LAZ/XYZ/TIF) │
│  - カラーマップ切り替え (RGB/X/Y/Z軸)   │
│  - リアルタイム統計表示                 │
└─────────────────┬───────────────────────┘
                  │
┌─────────────────▼───────────────────────┐
│  データローダー層                        │
│  - 5種類のフォーマット対応ローダー       │
│  - 座標正規化・境界ボックス計算          │
└─────────────────┬───────────────────────┘
                  │
┌─────────────────▼───────────────────────┐
│  空間データ構造 (Octree)                 │
│  - 8分木による階層的データ管理           │
│  - 視錐台カリング (LOD)                  │
└─────────────────┬───────────────────────┘
                  │
┌─────────────────▼───────────────────────┐
│  3層キャッシュシステム                   │
│  L1: GPU Buffer (最速)                   │
│  L2: LRU Cache (高速, メモリ)            │
│  L3: Persistent Cache (永続, ファイル)   │
└─────────────────┬───────────────────────┘
                  │
┌─────────────────▼───────────────────────┐
│  Web Worker プール (並列処理)            │
│  - 最大並列数 = CPU論理コア数 - 1        │
│  - LAZ解凍 (laz-perf WASM)               │
└─────────────────┬───────────────────────┘
                  │
┌─────────────────▼───────────────────────┐
│  WebGPU レンダリングパイプライン         │
│  - WGSL シェーダー (vec3/vec4対応)       │
│  - インスタンシング描画                  │
│  - 動的LODによる点サイズ調整             │
└──────────────────────────────────────────┘
```

### 主要技術
- **WebGPU/WGSL**: 最新GPU API による並列処理
- **Octree空間分割**: 効率的な階層的データ管理
- **アウトオブコア処理**: メモリに収まらない大規模データ対応
- **多層キャッシュ**: GPU Buffer → LRU → 永続化の3層構造
- **Web Worker**: UIをブロックしない並列データ取得

## 3. 実装・実験方法

### 3.1 対応ファイルフォーマット

| フォーマット | 拡張子 | ベクトル型 | 特徴 |
|------------|--------|-----------|------|
| COPC | `.copc.laz` | vec4 | ストリーミング対応、階層構造 |
| LAS | `.las` | vec3 | 非圧縮標準フォーマット |
| LAZ | `.laz` | vec3 | 圧縮版LAS（ファイルサイズ小） |
| XYZ | `.xyz` | vec3 | テキスト形式、シンプル |
| TIF/TIFF | `.tif`, `.tiff` | vec3 | ラスターから点群に変換 |

### 3.2 レンダリングパイプライン

#### Vec3レンダラー (LAS/LAZ/XYZ/TIF)
- Position: `vec3<f32>` (x, y, z)
- Color: `vec3<f32>` (r, g, b)
- 固定点サイズ (radius = 3.0)

#### Vec4レンダラー (COPC)
- Position: `vec4<f32>` (x, y, z, **LOD level**)
- Color: `vec3<f32>` (r, g, b)
- 動的点サイズ: `radius = 3.0 × 0.6^level`

### 3.3 カラーマップシステム

4種類の可視化モード:
1. **RGB Color**: 実際のRGB値
2. **Z-axis Color Map**: 高さに応じたグラデーション (青→赤)
3. **X-axis Color Map**: X座標に応じた色
4. **Y-axis Color Map**: Y座標に応じた色

実装: 20色のHSVグラデーションをGPUバッファに格納し、シェーダー内で補間

### 3.4 実験データセット
- **東京都内の建物点群データ** (LAS/LAZ)
- **農地の標高データ** (TIF)
- **河川領域の3D点群** (COPC)
- 規模: 数百万〜1億点以上

## 4. 結果・考察

### 4.1 パフォーマンス測定結果

| データサイズ | フォーマット | 初期読み込み時間 | 描画FPS | キャッシュヒット率 |
|------------|------------|----------------|---------|------------------|
| 500万点 | LAZ | 2.3秒 | 60 FPS | 85% |
| 1000万点 | COPC | 1.8秒 | 58 FPS | 92% |
| 5000万点 | COPC | 4.5秒 | 55 FPS | 88% |
| 1億点 | COPC | 7.2秒 | 52 FPS | 90% |

**考察**:
- COPCフォーマットは階層構造により初期読み込みが高速
- 1億点規模でも50 FPS以上を維持（実用的なレスポンス）
- キャッシュヒット率85%以上により、視点移動時の再描画が高速

### 4.2 3層キャッシュの効果

| キャッシュレベル | ヒット時の取得時間 | 容量 |
|----------------|------------------|------|
| L1: GPU Buffer | < 1ms | 小 (数百MB) |
| L2: LRU Cache | 5-10ms | 中 (数GB) |
| L3: Persistent | 20-50ms | 大 (数十GB) |
| キャッシュミス | 100-500ms | - |

**考察**:
- L1/L2キャッシュヒットで描画遅延を最小化
- L3永続キャッシュによりページリロード後も高速化
- キャッシュミス時でもWeb Worker並列処理で待機時間を短縮

### 4.3 カラーマップによる可視化

#### Z軸カラーマップの有効性
- 農地の高低差を色で直感的に把握可能
- 灌漑設計における水流シミュレーションに活用
- 従来のRGB表示では判別困難な微細な標高差を可視化

#### RGB vs 軸別カラーマップ
- RGB: 実際の色情報（植生、土壌の識別）
- Z軸: 高さ情報（排水計画、日照解析）
- X/Y軸: 空間的な位置関係の把握

## 5. 課題・Next Action

### 5.1 現在の主要な制限事項

#### P0（即時対応が必要）
- [ ] **LAZ v1.4 ネイティブサポート不足**
  - 現状: PDAL による事前変換が必要
  - 影響: ワークフロー複雑化、処理時間増加
  - 対策: laz-perf のアップデート待ち、または独自実装

- [ ] **エラーハンドリングの不統一**
  - 現状: console.error のみ
  - 影響: ユーザーがエラー原因を把握困難
  - 対策: トースト通知システムの実装

#### P1（優先度高）
- [ ] **複数ファイルの同時読み込み未対応**
  - 現状: 1ファイルのみ
  - 影響: 広域データの統合可視化ができない
  - 対策: 複数Octreeの統合管理システム実装

- [ ] **GPU Bufferのラベリング不足**
  - 現状: デバッグ困難
  - 影響: 開発効率低下
  - 対策: 全GPUリソースに意味のあるラベル付与
