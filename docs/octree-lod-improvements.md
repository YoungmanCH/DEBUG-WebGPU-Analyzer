# Octree LOD可視化の修正と改善

## 概要

このドキュメントでは、COPC（Cloud Optimized Point Cloud）ファイルのoctree構造を利用した大規模点群データの階層的可視化機能の修正と改善について説明します。

## 修正内容

### 1. 重大なバグ修正 (`src/octree/octree-traverser.ts`)

**問題**: 子ノードの存在チェックで間違ったキーを参照していた

```typescript
// 修正前（バグ）
if (!(key1 in nodePages && nodePages[key].pointCount > 0)) {
  return [];
}

// 修正後
if (!(key1 in nodePages && nodePages[key1].pointCount > 0)) {
  return;
}
```

このバグにより、octreeの子ノードが正しく探索されず、全ノードをロードしようとしていました。

### 2. LODアルゴリズムの改善

**追加した機能**:
- カメラからの距離に基づく適切なレベル選択
- スクリーン投影サイズによる動的LOD判定
- 最大探索深度の制限（メモリ節約）

**設定パラメータ** (`LOD_CONFIG`):
```typescript
const LOD_CONFIG = {
  minScreenPixels: 50,        // これ以上大きければ子ノードを探索
  prefetchScreenPixels: 100,  // プリフェッチ用の閾値
  maxLevel: 15,               // 最大探索深度
};
```

**可視性判定の3段階**:
- `0`: 非表示（視錐台外または遠すぎる）
- `1`: このノードを表示（適切なLODレベル）
- `2`: 子ノードを探索（より詳細な表示が必要）

### 3. 視錐台カリング

**改善内容**:
- ノードの境界球を使った可視性判定
- カメラからの距離と視野角を考慮
- 近すぎる場合の特別処理

**主な実装**:
```typescript
// ノードの境界球がカメラから見えるかチェック
const sphereRadius = radius * Math.sqrt(3); // ボックスを囲む球の半径
const maxVisibleDistance = sphereRadius + (screenHeight / (2 * tan(fov / 2)));
```

### 4. メモリ管理機能 (`src/utils/memory-manager.ts`)

**新規追加**: 大規模データ対応のためのメモリ管理システム

**主な機能**:
- 最大ノード数の制限（5000ノード）
- 未使用ノードの自動解放
- フレームベースのアクセス追跡
- GPUバッファの適切な破棄

**設定**:
```typescript
const MEMORY_CONFIG = {
  maxBufferNodes: 5000,      // 最大保持ノード数
  deleteThreshold: 500,      // 一度に削除するノード数
  maxIdleFrames: 300,        // 未使用判定の閾値（約5秒）
};
```

**統合** (`src/webgpu/webgpu-renderer.ts`):
- 60フレームごとに自動クリーンアップ
- メモリ使用率が80%を超えると警告
- 現在表示中のノードは保護

### 5. octreeトラバーサルの最適化

**改善内容**:
- 子ノードの中心座標の正確な計算
- 子ノードが存在しない場合の早期リターン
- 子ノードが何も返さなかった場合の親ノード表示

**修正後のロジック**:
```typescript
// 可視性判定に基づく処理分岐
if (visibility === 0) {
  return []; // 非表示
}
if (visibility === 1) {
  return [key, nodePages[key].pointCount]; // このノードを表示
}
// visibility === 2: 子ノードを探索
```

## 大規模データ（1TB）への対応

### COPCファイルが提供するもの
- ✅ 既に構築されたoctree構造
- ✅ 階層的なページ分割
- ✅ 部分的データアクセス（ファイルオフセット指定）

### 今回の修正で追加した機能
- ✅ 視錐台カリング（カメラに見えるノードだけ選択）
- ✅ LODアルゴリズム（距離に応じた階層レベル選択）
- ✅ 動的ストリーミング（必要なノードのみロード）
- ✅ メモリ管理（使わないノードを自動解放）

## パフォーマンスへの影響

### メモリ使用量
- **制限前**: 無制限（全ノードをロード）
- **制限後**: 最大5000ノード（設定可能）
- **削減率**: データサイズに依存（大規模データほど効果大）

### レンダリング性能
- カメラに近い領域は高解像度
- 遠い領域は低解像度
- 視野外のノードは非表示

### ロード時間
- 必要なノードのみロード
- プリフェッチによる先読み
- 段階的な詳細化

## 使用方法

### 設定のカスタマイズ

**LOD閾値の調整** (`src/octree/octree-traverser.ts`):
```typescript
const LOD_CONFIG = {
  minScreenPixels: 50,  // 小さくすると早めに詳細表示
  maxLevel: 15,         // 大きくするとより深く探索
};
```

**メモリ制限の調整** (`src/utils/memory-manager.ts`):
```typescript
const MEMORY_CONFIG = {
  maxBufferNodes: 5000,  // メモリに余裕があれば増やす
  maxIdleFrames: 300,    // 小さくすると積極的に解放
};
```

### デバッグ情報

コンソールに以下の情報が出力されます:

- `[Memory] Cleaned up N nodes`: メモリクリーンアップの実行
- `[Memory] High utilization: X/Y (Z%)`: メモリ使用率が高い警告

## 今後の改善案

1. **より正確な視錐台カリング**
   - プロジェクション行列を使った完全な視錐台判定
   - AABB（軸平行境界ボックス）との交差判定

2. **適応的LOD閾値**
   - GPUパフォーマンスに応じた動的調整
   - ネットワーク速度を考慮したプリフェッチ

3. **マルチスレッドローディング**
   - Web Workerを使った並列ノードロード
   - バックグラウンドでのプリフェッチ

4. **圧縮データの対応**
   - LAZの直接デコード
   - ストリーミング解凍

## まとめ

今回の修正により、COPCファイルの持つoctree構造を活用した大規模点群データ（1TB含む）の階層的可視化が可能になりました。主な改善点は:

1. ✅ octree探索の致命的なバグを修正
2. ✅ 距離ベースのLODアルゴリズムを実装
3. ✅ 視錐台カリングによる不要なノードの除外
4. ✅ メモリ管理システムによる自動リソース解放

これにより、シンプルなCOPCファイルの読み込みだけでなく、**賢い選択的ロードとメモリ管理**が実現され、大規模データの実用的な可視化が可能になりました。
